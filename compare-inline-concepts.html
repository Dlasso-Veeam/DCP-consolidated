Concept A · recommended

Summary cell + inline expand (master–detail)

One row per record with a compact change summary; click to expand the changed fields in place. Scan breadth like a table, drill depth without a drawer.

Scales to many fields (collapsed + changed-only) One row per record — table stays scannable No drawer round-trips Detail needs a click

Concept B

Single "Changes" column — old → new chips

A fixed-width column shows the first couple of changes as field: old → new chips, with a "+N more" overflow that expands inline. Width stays bounded no matter how many fields exist.

Top changes visible with zero clicks Bounded width Only a peek until expanded Chips get busy on high-churn rows

Concept C

Stacked before/after — curated "watched" columns

A handful of key fields become real columns, each cell stacking old over new. Everything else collapses into a "+N other changes" link. Best when a few fields matter most.

Zero clicks for the fields that matter Reads like a spreadsheet diff Doesn't scale to arbitrary fields — only the curated set Needs someone to choose the watched fields

Concept D · novel

Change-density strip — the table as a change radar

Each record gets a per-field tick strip, fields aligned across rows. The point isn't one record — it's the vertical bands: a column lit up everywhere means a field that changed fleet-wide (a bulk reassignment, a migration). Hover any tick for its before→after and how many records share that change. This answers a question no drawer can.

Reveals fleet-wide patterns at a glance Zero clicks; all fields visible at once Tiny footprint — scales to many fields Values are hover-only (overview, not deep read)
Each tick = one field, in the same order every row. ▮ modified · ▮ added · ▮ removed · ▮ unchanged. Hover to inspect; the column highlights across all records.

Concept E · novel

Auto-pivot — the most-changed fields become before/after columns

No hand-picked columns and no click: the table computes its columns as the fields that changed in the most records (the same bands the radar surfaces), each cell stacking old over new. Per-record long-tail changes collapse into "+k". It's a real, sortable diff grid that stays bounded because columns track frequency of change, not field count.

Inline before/after with zero clicks, zero curation Bounded width (top-N changed fields) Sortable grid — "who changed Status?" Rare per-record fields live in the "+k" overflow
